# 用户群聊

## 功能范围

用户群聊是站内轻量公共聊天室，入口位于用户左侧栏的“用户群聊”，页面路径为 `/community-chat`。

当前实现包含：

- PostgreSQL 持久化文本、图片和文件附件消息。
- WebSocket 实时推送群聊/私聊的新消息和删除事件；多实例部署通过 Redis Pub/Sub 转发事件。
- 附件上传，支持 JPEG、PNG、GIF、WebP、MP4、PDF、Office 文档、Markdown、文本、CSV、RTF，单个最大 15 MB。
- 图片消息可在群聊内点开放大查看，也可下载；文件附件以文件卡片展示并支持按原文件名下载。
- MP4 视频消息会以内嵌播放器展示，也可点“放大播放”在弹窗中播放，并提供下载入口。
- 群聊输入框右下角提供完整 Unicode Emoji 选择器，支持中文/英文搜索、分类浏览、常用表情、肤色选择和键盘操作；表情会插入当前光标或替换选中文本。Emoji 数据随前端本地发布，不依赖第三方 CDN，常用记录只保存在当前浏览器。
- 群聊输入框会随文字行数向上增高，达到约六行后改为输入框内部滚动，发送或清空后自动缩回单行。
- 图片、MP4 和支持的文档可直接拖入群聊区域，拖放时显示投放提示；松开后只进入发送预览，不会自动发送。现有上传按钮和粘贴图片仍可使用。
- 群聊标题栏支持按消息正文或发送者名称搜索全部未撤回历史消息。搜索后展示当前命中消息前后各 20 条连续聊天记录，而不是只罗列命中消息；工具栏显示“当前结果/总数”，可用上下箭头逐条切换，按消息列表可视区域将正文关键词、发送者名称或媒体文件名精确居中。上下文中的全部字面命中词都会高亮，当前结果使用更强的标记；图片或视频尺寸加载完成后会重新校准当前结果，跨页时自动加载后续结果。搜索期间新消息不会打断当前位置，退出后恢复搜索前的群聊滚动位置。
- 所有用户可回复其他人的消息。
- 用户可撤回自己发送的群聊和私聊消息，管理员可删除任意群聊和私聊消息；私聊删除同样采用软删除并实时同步给会话双方。
- 新发言会记录并显示发送时间；历史消息不回填发送时间。
- 左侧栏“用户群聊”入口会在收到其他用户的新群聊或私聊消息时，在菜单文字旁显示闪烁红点；进入群聊页本身不会隐藏提醒，群聊阅读事件只清除群聊提醒，私聊按服务端实际未读状态清除，有任一未读仍显示。群聊已读位置保存在当前浏览器，私聊未读位置保存在服务端并按阅读者和用户会话分别统计。
- 群聊页提供“私聊站长”入口，普通用户可与站长私聊；私聊与群聊支持相同的图片、MP4 和文件附件类型，图片可放大、视频可预览、普通文件可下载。
- 群聊标题栏中间使用显著的大按钮提供“私聊站长”入口，移动端独占一行居中展示，不与搜索和在线状态挤在同一操作组。私聊输入框与主群聊一致，会随内容自动增高、在约六行处转为内部滚动，并在发送、清空或重新打开后恢复合适高度。管理员可通过用户名或邮箱搜索尚未建立会话的用户并主动发送第一条私信；已有会话列表使用固定高度独立滚动并支持分页加载，不随用户数量无限拉长。会话列表显示每个用户的独立未读数，只有私聊窗口可见且停留在消息底部时才标记当前会话已读。
- 群聊和私聊均支持向上加载历史，加载后保持原滚动位置。用户停留在底部时自动跟随新消息；查看历史时保持当前位置并显示新消息计数按钮；本人发送的消息始终自动跟随到底部。
- 发送接口成功后立即把返回消息加入页面；WebSocket 初始化和断线重连后会按消息游标补拉遗漏消息。侧边栏与聊天页共用一条浏览器 WebSocket 连接。

当前实现不包含贴纸/GIF 表情商店、频道、群聊跨设备已读回执、在线人数、对象存储适配和消息审核工作流。

## 数据与文件

数据库迁移会创建 `community_chat_messages` 表，保存消息正文、消息类型、用户快照、附件地址、回复快照、发送时间和软删除信息。发送时间字段只对新增消息写入，历史消息保持为空。

站长私信使用 `community_chat_direct_messages` 表，按 `conversation_user_id` 保存普通用户与管理员之间的一对一会话、附件元数据和软删除信息。`community_chat_direct_read_states` 按阅读者及用户会话保存最后已读消息，普通用户只能访问自己的会话；管理员可搜索活跃普通用户、主动发起会话并指定用户回复。

附件默认保存在服务端本地目录：

```text
<DATA_DIR>/chat/uploads
```

其中 `DATA_DIR` 使用现有定价配置里的数据目录。容器化部署时需要确保该目录所在卷持久化，否则重建容器后历史附件文件可能丢失。

## 接口

所有消息读写接口都需要登录态：

```text
GET    /api/v1/community-chat/messages?page=1&page_size=50
GET    /api/v1/community-chat/messages?search=<KEYWORD>&page=1&page_size=50
GET    /api/v1/community-chat/messages?before_id=<MESSAGE_ID>&limit=80
GET    /api/v1/community-chat/messages?after_id=<MESSAGE_ID>&limit=100
POST   /api/v1/community-chat/messages
POST   /api/v1/community-chat/files
POST   /api/v1/community-chat/images
POST   /api/v1/community-chat/attachments/session
DELETE /api/v1/community-chat/messages/:id
```

`search` 使用大小写不敏感的字面包含匹配，查询消息正文和发送者名称；`%`、`_` 等字符不会被解释为通配符。搜索不可与 `before_id` 或 `after_id` 同时使用。

发送文字消息时可传入 `reply_to_message_id`：

```json
{
  "content": "收到，我试一下",
  "reply_to_message_id": 123
}
```

上传附件消息使用 multipart 表单字段 `file`，可附带 `content` 和 `reply_to_message_id`。`content` 作为用户输入的说明文字；下载文件名使用上传时的原文件名。`POST /api/v1/community-chat/images` 保留为旧图片上传兼容入口，仍接受 `image` 字段。

站长私信接口：

```text
GET    /api/v1/community-chat/direct/conversations
GET    /api/v1/community-chat/direct/users?search=<USERNAME_OR_EMAIL>
GET    /api/v1/community-chat/direct/messages?user_id=<USER_ID>
GET    /api/v1/community-chat/direct/messages?user_id=<USER_ID>&before_id=<MESSAGE_ID>&limit=80
GET    /api/v1/community-chat/direct/messages?user_id=<USER_ID>&after_id=<MESSAGE_ID>&limit=100
GET    /api/v1/community-chat/direct/unread
POST   /api/v1/community-chat/direct/read
POST   /api/v1/community-chat/direct/messages
POST   /api/v1/community-chat/direct/files
DELETE /api/v1/community-chat/direct/messages/:id
```

普通用户调用私信消息接口时无需传 `user_id`，后端固定使用当前登录用户。管理员查看或回复某个用户会话时需要传 `user_id`。

`GET /direct/users` 仅管理员可用，只搜索状态正常的普通用户并返回用户 ID、显示名称和头像。管理员可据此选择一个尚无私信历史的用户，直接通过文本或附件接口发送第一条消息，无需预先创建会话。

标记已读时，`POST /direct/read` 必须包含页面实际显示的最后一条消息 ID：普通用户传 `{"last_message_id": 456}`，管理员传 `{"user_id": 123, "last_message_id": 456}`。服务端只推进到该会话中不超过此 ID 的消息，不会把并发到达但尚未展示的消息标为已读；历史加载期间不提交已读。缺少或非法 ID 返回 400，部署后旧页面需刷新以使用新请求格式。私聊删除权限与群聊一致：发送者可删除自己的消息，管理员可删除任意消息。

发送私信：

```json
{
  "content": "我想咨询一下账号使用问题",
  "user_id": 123
}
```

发送私聊附件使用 multipart 表单；字段 `file` 必填，`content` 可选。管理员必须同时传 `user_id`，普通用户即使传入其他 `user_id`，后端仍固定写入本人的站长会话：

```text
file=<IMAGE_OR_FILE>
content=<OPTIONAL_CAPTION>
user_id=<ADMIN_ONLY_TARGET_USER_ID>
```

附件读取需要有效登录态。前端会先调用附件会话接口，将当前 Bearer JWT 换成一个仅限附件路径、5 分钟有效的 HttpOnly Cookie，并在聊天室打开期间续期。服务端每次读取仍会校验 JWT、用户状态、令牌版本和后端模式；群聊附件对合法登录用户可见，私聊附件仅对应普通用户和管理员可读取。也可直接使用 Bearer JWT 请求附件。

附件读取：

```text
GET /api/v1/community-chat/uploads/:filename
```

下载附件时可追加 `download=1`：

```text
GET /api/v1/community-chat/uploads/:filename?download=1
```

消息被撤回或管理员删除后，服务端会先软删除数据库消息，再删除本地附件。即使本地文件删除失败，已删除消息对应的附件也会因数据库状态检查而返回 404。

附件响应使用 `Cache-Control: private, no-store`，避免登录失效或消息删除后继续命中浏览器/代理缓存；同时发送 `X-Content-Type-Options: nosniff`，禁止浏览器对上传文件进行 MIME 猜测。

实时消息：

```text
GET /api/v1/community-chat/ws
```

浏览器 WebSocket 通过子协议列表 `sub2api-chat, jwt.<JWT>` 传递当前 JWT。服务端只协商并回显 `sub2api-chat`，JWT 不进入 URL 或握手响应。浏览器来源默认必须与请求主机一致；跨域部署需将前端来源明确加入 `cors.allowed_origins`。

WebSocket 会推送公共群聊事件和站长私信事件。公共群聊新消息仍会触发左侧栏红点；私信事件只发送给对应普通用户和管理员，不会广播给所有在线用户。

## 运维注意

- 该功能依赖 PostgreSQL 迁移正常执行。
- 附件保存在本地文件系统，生产环境应确认 `DATA_DIR` 对应目录有持久化卷；多实例部署必须让所有实例共享该附件目录，否则数据库消息可见但其他实例无法读取文件。
- 附件 Cookie 仅作用于 `/api/v1/community-chat/uploads`；前后端分离部署时应通过同源反向代理暴露该路径，确保浏览器原生图片和视频请求可携带 Cookie。
- WebSocket 需要反向代理支持连接升级；应用实例需要连接同一个 Redis，才能互相转发实时聊天事件。
- 文本消息、私聊消息和删除操作按客户端 IP 限制为每分钟 30 次，附件上传每分钟 6 次。Redis 限流故障时采用放行策略，不阻断已登录用户聊天。
- 群聊提醒按当前浏览器已读位置恢复；私聊提醒按服务端已读位置恢复，支持跨浏览器和跨设备保持一致。
- 如部署在后端模式，普通用户群聊接口会沿用现有用户自助访问限制。

## 2026-09-15 体验修复 1：断线补拉

群聊与当前私聊在重连回调中立即开始独立补拉，不再等待未读统计或另一会话完成后才取游标。空会话重连时重新加载最近一页，恢复断线期间收到的首条消息。

## 2026-09-15 体验修复 2：私聊历史与实时消息合并

每次打开私聊先建立新的消息加载会话；历史返回时与本次加载期间收到的实时消息按 ID 合并。重新打开不沿用旧快照，切换用户后忽略旧请求，避免覆盖新消息或混入另一会话。

## 2026-09-15 体验修复 4：私聊草稿隔离

管理员切换私聊对象时，文字草稿按用户分别暂存于当前页面内；切回可恢复，附件仍在切换时清空。发送响应晚到只清理原收件人的已提交草稿，不会清空另一人的同文草稿。关闭当前私聊仍清空当前输入，刷新页面不保留草稿。

## 2026-09-15 体验修复 5：输入法确认

群聊和私聊均在输入法组合输入期间保留 Enter 的候选词确认行为；正常 Enter 发送，Shift+Enter 换行，同时兼容组合输入 keyCode 229。

## 2026-09-15 体验修复 6：长记录输入流畅性

群聊与私聊复用未变化消息的渲染结果，并按语言复用时间格式器，避免每次输入都重新处理全部历史。消息更新、搜索高亮、撤回状态和语言切换仍会刷新对应内容；本轮不裁剪历史，也未引入虚拟滚动。

## 2026-09-15 体验修复 7：管理员会话列表刷新

收到私信、发送或删除消息后，管理员会话列表静默刷新已加载的分页，保留当前行位置和已加载会话，不切回整页加载动画。刷新期间连续到达的消息合并为后续刷新，避免旧响应反向覆盖新内容；首次打开仍正常加载。

## 2026-09-15 体验修复 8：附件会话恢复

附件会话初始化不阻塞文字历史。初始化或续期失败后每 30 秒重试，成功后每 4 分钟续期；重连或切回页面时也尝试恢复，同一时刻复用一个请求。恢复成功只重试已加载失败的图片/视频，不重载正常播放内容；离开页面清理计时器。

## 2026-09-15 体验修复 9：附件上传进度与超时

群聊及私聊附件上传单独使用 10 分钟客户端超时，其他 API 仍沿用原超时。上传时显示百分比（总长度未知时显示上传中），传输达到 100% 后提示等待发送确认，只有服务端成功响应才清空原草稿和附件。失败保留输入供检查后重试，不自动重复发送。管理员切换对象时，不把上一人的上传进度显示在另一会话。

此设置不能覆盖反向代理的请求大小或超时限制；部署侧仍需允许 15 MB 附件及足够的上传时间。

## 2026-09-15 联合验证与发布

重连补拉期间暂停私信已读提交，待缺失消息合并并渲染后再按已显示的消息上限推进。前后端需一起发布，旧页面刷新后才能使用新的已读参数；不涉及数据库迁移。聊天回归、后端相关单元测试、前端检查与生产构建已通过，尚未进行生产环境断网/慢速上传验收。

## 2026-09-15 私聊站长入口外观

标题栏居中的私聊入口使用 64px 高的香槟淡金渐变按钮，32px 对话图标置于 44px 珠光底座中，并配有小星光装饰。图标轻微浮动，按钮间歇掠过柔和高光，悬停时轻微抬升；尊重系统“减少动态效果”设置，使用纯 CSS 动效。入口下方显示“小问题请直接私聊”，支持中英文和明暗主题；保留原私聊打开动作及未读提醒。

## 2026-09-16 私聊未读提醒

用户和站长共用入口右上角的 24px 高红色“新消息”徽标，搭配铃铛、浅色描边及轻微外圈呼吸效果，替代原 10px 闪烁红点。徽标定位不挤动按钮内容，文字保持常亮，支持屏幕阅读器及减少动态效果设置；沿用原有未读状态和已读消除逻辑，不把提示文字当作消息数量。
